# PURPOSE

This document defines the official writing standard used throughout the ORVIO Production Operating System.

Every document inside OPOS must follow this standard.

No document may define its own format.

---

# OBJECTIVES

The documentation standard exists to ensure:

- Consistency
- Readability
- Maintainability
- AI compatibility
- Human readability
- Long-term scalability

---

# DOCUMENT HEADER

Every OPOS document must begin with the following metadata.

- Document ID
- Document Name
- Version
- Status
- Owner
- Dependencies
- Required Reading
- Next Document

No document may omit this section.

---

# WRITING STYLE

Documents must use:

- Clear English.
- Short sentences.
- Technical wording.
- Imperative rules where appropriate.

Avoid:

- Storytelling.
- Marketing language.
- Personal opinions.
- Ambiguous wording.

---

# DOCUMENT STRUCTURE

Every document should follow this order whenever applicable.

1. Purpose

2. Scope

3. Definitions

4. Rules

5. Workflow

6. Examples

7. Exceptions

8. Revision Notes

Not every section is mandatory, but the order must remain consistent.

---

# RULE WRITING

Rules must:

- Be explicit.
- Be testable.
- Be reproducible.
- Avoid subjective language.

Correct:

"The AI must request missing information."

Incorrect:

"The AI should probably ask for more information."
